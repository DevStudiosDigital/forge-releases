Install Forge on your server

One signed file installs the Control Station, the MCP Server and the Orchestrator on one Linux server. It takes a few minutes, and the installer checks your server before it changes anything.

Downloads

You need all three files. Step 1 below shows how to get them onto your server. The installer needs no internet access once it is there.

forge-install-0.1.5.shThe installer, about 810 MB forge-install-0.1.5.sh.sigIts signature fc.pubThe Forge public key, to check the signature

What the server needs

  • Linux on amd64 (x86-64) or arm64, with systemd, and sudo access
  • Docker with Compose v2, or Podman 5 or later with podman compose. On Ubuntu 22.04 use Docker, because its Podman is too old.
  • openssl and curl, which most servers already have
  • About 3 GB free disk for /opt/forge, 2 GB free in /var/tmp while the installer unpacks, and 1.5 GB free memory, plus what your model needs
  • A local ext4 or XFS disk for /opt/forge and for the container storage (not NFS)
  • Ports 8080, 8081 and 8084 free, and open to your internal network in the server's firewall if it has one. 9090 and 9091 are used locally only.
  • The clock synced over NTP

Only if you want them (you can also add them later)

  • A model, one of these: Forge runs it with Ollama: an Ollama image in your registry (ollama/ollama:0.40.9) and a folder with the GGUF file and a Modelfile. Forge runs it with vLLM: a vLLM image (vllm/vllm-openai:v0.32.0), a model folder, and an NVIDIA GPU with the NVIDIA container toolkit. You already run it: the address of your Ollama, vLLM or other OpenAI-compatible server, and its API key if it has one.
  • Your private CA file, if your internal APIs or the model use certificates from it
  • Your own certificate and key for the chat API. Without them, Forge creates its own.
  • A Bitwarden or Vaultwarden server, if your APIs keep their secrets there

1Put the files on the server

Use either way. Both end with the three files in one folder on the server.

ADownload in your browser, then copy to the server

Click each file to save it to your computer:

forge-install-0.1.5.shDownload forge-install-0.1.5.sh.sigDownload fc.pubDownload

If the browser warns that a file is not commonly downloaded, choose Keep. Then copy the three files to the server with any file-transfer tool (WinSCP, FileZilla, Cyberduck), or from a terminal in your Downloads folder (macOS, Linux, and Windows PowerShell):

your computer
scp forge-install-0.1.5.sh forge-install-0.1.5.sh.sig fc.pub \
    admin@your-server:

Replace admin@your-server with your user and server. The files land in your home folder there.

BDownload straight on the server

If the server can reach the internet, run this on it:

server
F=forge-install-0.1.5.sh
U=https://github.com/DevStudiosDigital/forge-releases/releases/download/v0.1.5
curl -fL -O $U/$F -O $U/$F.sig -O $U/fc.pub

2Check the signature

On the server, in the folder with the three files:

server
F=forge-install-0.1.5.sh
base64 -d $F.sig > forge-install.sig
openssl dgst -sha256 -verify fc.pub -signature forge-install.sig $F

It must print Verified OK. If it prints anything else, stop and contact us: the file is damaged or is not from Forge.

3Run the installer

server
sudo sh forge-install-0.1.5.sh

If you are logged in as root, leave out sudo here and in every command below.

It first checks the server and lists anything missing, with the fix. Then it asks:

  1. The first admin's username and password (at least 14 characters).
  2. Do you have your own certificate? Answer n and Forge creates one. It then shows the names and IPs it found; add any other name or IP your apps use to reach this server, such as a public IP or DNS name.
  3. Optional setup: a model, your private CA, Bitwarden. Press Enter to skip them; you can add each one later. For a model Forge runs with Ollama it asks for the Ollama image, the folder that holds the GGUF file and its Modelfile (whose FROM line names the GGUF file), and the model's context window; press Enter to keep the default.
If you connect a model server you already run, the installer calls it from the server and from inside Forge before saving anything, and tells you what to fix if it cannot reach it. A server on the same machine must listen on 0.0.0.0, not only on 127.0.0.1.

4Open Forge

At the end the installer prints the addresses for your server. They look like this:

WhatAddressSign in with
Control Stationhttp://<server>:8084/The admin you just created
Chat API for apps (OpenAI-compatible)https://<server>:8080/v1The API key, sent as X-API-Key: <key> or Authorization: Bearer <key>. Show it with sudo cat /opt/forge/stack/secrets/orch-api.key
MCP clientshttp://<server>:8081/mcpThe MCP token, sent as Authorization: Bearer <token>. Show it with sudo cat /opt/forge/stack/secrets/mcp.token

Apps ask for the model accurate. With the certificate Forge created, give them the file /opt/forge/stack/certs/forge-ca.pem so they trust the chat API.

The Control Station (8084) and MCP Server (8081) use plain HTTP. Reach them only over your internal network or VPN.

5Publish your first tool

A tool is one operation of one of your APIs, which Forge's chat and your MCP clients can then call.

  1. Store the API's token, if it needs one. The Control Station never takes the token itself, only a reference to it. On the server:
    server
    sudo forge secret add inventory-token
    It asks for the value (hidden) and prints the reference to use, here file:/secrets/inventory-token.
  2. Add the API. In the Control Station open MCP Server → APIs → Add API: Name: 3 to 64 lowercase letters, digits, - or _, for example inventory. Base URL: the API's address as the Forge server reaches it, a name or IP on your network. Never localhost or 127.0.0.1: those point inside Forge. For an API on the Forge server itself use host.docker.internal, and make the API listen on 0.0.0.0. Turn on Allow HTTP if the address starts with http://. Auth type: how the API expects the token (bearer or api_key), with the reference from step 1 in Token ref. Save, then Test connection. It checks that the address answers (any HTTP status, even 404, passes); the token is checked when you test a tool. If it fails, check the base URL can be reached from the Forge server.
  3. Import its operations. Open Import OpenAPI, pick the API, choose its OpenAPI file (JSON or YAML), then Preview operations, select the ones you want and click Import. They become draft tools, named after each operation's operationId; tool names are unique across all APIs, so an operation whose name is already taken is skipped.
  4. Test and publish. Open Tools, pick one and run Test. For a tool that changes data, first tick the box confirming the test calls the real API. Then click Publish, add a comment and confirm. The tool is now live for the chat API and for MCP clients. Forge's chat asks the user to confirm before a tool that changes data runs. MCP clients can run such tools only if they support that confirmation (MCP 2026-07-28); others can run read tools.

The full release package

The installer also saves the complete signed release to /opt/forge/release/forge-stack-0.1.5.tar: source code, SBOMs, vulnerability scan reports with their database, Helm charts, the command-line programs and the chat widget for your own apps. Forge does not need it to run; keep it for your records and security reviews. To look inside:

server
mkdir -p ~/forge-release && tar -xf /opt/forge/release/forge-stack-0.1.5.tar -C ~/forge-release
cat ~/forge-release/forge-stack-0.1.5/IMPORT.md

To verify the package and each product inside it, run sections 1 and 2 of IMPORT.md from ~/forge-release, with KEY set to the fc.pub you downloaded in step 1. Its install-by-hand sections are not needed on a server set up with the installer.

If something goes wrong

Fix what the installer reports and run the same command again. It keeps what it already set up and asks the questions again.

If you need us, run this and send us the file it names, /var/tmp/forge-doctor-<server>-<time>.tar.gz. It contains no keys or passwords. Only root can read it, so copy it with sudo cp first.

server
sudo forge doctor

If the install stopped before Forge was set up, send /var/log/forge-install.log instead.
