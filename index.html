Install Forge on your server

A small installer and a signed release package set up Forge on a Linux server in a few minutes. The installer checks the package and the server before it changes anything.

What the server needs

  • Linux (amd64 or arm64) with systemd and sudo
  • Docker with Compose v2, or Podman 5+ (on Ubuntu 22.04, use Docker)
  • openssl and curl
  • 3 GB free in /opt/forge, 300 MB in /var/tmp, 1.5 GB of memory, plus what the model needs
  • A local ext4 or XFS disk (not NFS)
  • Ports 8080, 8081 and 8084 free and open to your network
  • Clock synced (NTP)

Optional, can be added later

  • A model, one of: Ollama image (ollama/ollama:0.40.9) and a folder with the GGUF file and its Modelfile vLLM image (vllm/vllm-openai:v0.32.0), a model folder and an NVIDIA GPU The address of a model server you already run
  • Your private CA file
  • Your own certificate and key (otherwise Forge creates one)
  • A Bitwarden or Vaultwarden server

1Put the files on the server

You need five files, in one folder on the server.

ADownload in your browser, then copy

If the browser warns, choose Keep. Copy the files to the server with WinSCP, FileZilla, or from a terminal in your Downloads folder:

your computer

Replace admin@your-server with your login.

2Check the signature optional

Recommended. In the folder with the files:

server
F=forge-install-0.1.6.sh
base64 -d $F.sig > forge-install.sig
openssl dgst -sha256 -verify fc.pub -signature forge-install.sig $F

It must print Verified OK. If not, contact us. The installer checks the release package's signature itself.

3Run the installer

server
sudo sh forge-install-0.1.6.sh

It checks the package's signature and the server, then asks the questions below. If the package is in another folder, it asks for its path.

  1. Admin username and password (14+ characters)
  2. Your own certificate? Answer n and Forge creates one. Add any other name or IP apps use, such as a public IP.
  3. Optional setup: model, private CA, Bitwarden. Press Enter to skip.
Using a model server you already run? It must listen on 0.0.0.0, not only 127.0.0.1. The installer tests it before saving.

4Open Forge

The installer ends by printing your addresses:

WhatAddressSign in with
Control Stationhttp://<server>:8084/The admin you created
Chat API (OpenAI-compatible, model accurate)https://<server>:8080/v1API key: sudo cat /opt/forge/stack/secrets/orch-api.key
MCP clientshttp://<server>:8081/mcpBearer token: sudo cat /opt/forge/stack/secrets/mcp.token

Give apps /opt/forge/stack/certs/forge-ca.pem so they trust the chat API.

Ports 8084 and 8081 use plain HTTP. Keep them on your internal network.

5Publish your first tool

  1. Store the API's token (if it has one):
    server
    sudo forge secret add inventory-token
    It prints a reference like file:/secrets/inventory-token.
  2. Add the API: in the Control Station, MCP Server → APIs → Add API. Base URL: the API's address on your network, not localhost. For an API on this server, use host.docker.internal. Turn on Allow HTTP for http:// addresses. Put the reference in Token ref. Save, then Test connection.
  3. Import: Import OpenAPI → pick the API → choose the file → Preview operations → Import.
  4. Publish: Tools → pick a tool → Test → Publish.

6Add chat to your website optional

Forge already serves a chat window. One script tag adds it to any website, such as plain HTML, Angular or WordPress. Answers stream as they are written, and users see when a tool runs and approve tools that change data.

  1. Allow your website. Browsers can reach the chat API only from sites you list. On the server, set O to your site's address (https://host or https://host:port, no path), then run:
    server
    O=https://intranet.example.com
for f in /opt/forge/stack/config/orchestrator/orchestrator.*.yaml; do
  sudo grep -q '^cors:' "$f" || printf 'cors:\n  allowed_origins:\n' | sudo tee -a "$f" >/dev/null
  sudo grep -qx "    - $O" "$f" || sudo sed -i "/^  allowed_origins:/a\    - $O" "$f"
done
sudo systemctl restart forge-stack
    Run it again for each extra site. Upgrades and forge setup keep the list.
  2. Make browsers trust the chat API. Your users' browsers must trust its certificate. Either install /opt/forge/stack/certs/forge-ca.pem on their computers (for example by group policy), or use a certificate they already trust: sudo forge setup https.
  3. Add the tag to your pages, with your server's address:
    your website
    <script src="https://forge.example.com:8080/static/fc-chat.js"
  data-endpoint="https://forge.example.com:8080"
  data-token="API-KEY" defer></script>
    Replace API-KEY with the chat API key (sudo cat /opt/forge/stack/secrets/orch-api.key). A chat button appears at the bottom right. If the site has a Content Security Policy, add the Forge address to script-src and connect-src.
Anyone who can open the page can read the API key in it and use the chat API. Put it only on pages that just your staff can open. For other pages, sign users in as shown below.

Sign users in with your SSO

The chat then uses each user's own token, and their roles decide which tools they can use. In each file from step 1, replace the auth: block with your identity provider's details, then restart as in step 1:

orchestrator.*.yaml
auth:
  mode: jwt
  jwt:
    issuer: https://sso.example.com
    audience: forge
    jwks_url: https://sso.example.com/.well-known/jwks.json
    roles_claim: roles

Then load the chat with a function that returns the signed-in user's token, instead of data-token:

your website
<script src="https://forge.example.com:8080/static/fc-chat.js"></script>
<script type="module">
  FCChat.mount({
    endpoint: "https://forge.example.com:8080",
    token: () => myApp.getAccessToken()
  });
</script>
With SSO on, the API key stops working. Other apps that call the chat API must then send a user token too.

React apps can use the npm package instead. It is in the release package on the server. Publish it to your internal npm registry:

server
tar -xf /opt/forge/release/forge-stack-0.1.6.tar --strip-components=2 \
    forge-stack-0.1.6/products/forge-chat-0.1.0.tar
tar -xf forge-chat-0.1.0.tar
npm publish forge-chat-0.1.0/npm/forcecapacity-chat-0.1.0.tgz \
    --registry https://npm.example.com/

Then run npm install @forcecapacity/chat in your app and add <ForceCapacityChat endpoint="https://forge.example.com:8080" token={getToken} />. forge-chat-0.1.0/IMPORT.md has the details.

If something goes wrong

Fix what the installer reports and run it again. It keeps what it already set up.

To get help, run this and send us the file it names. It holds no keys or passwords.

server
sudo forge doctor
