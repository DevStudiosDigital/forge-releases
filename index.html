Install Forge on your server

One signed file installs the Control Station, the MCP Server and the Orchestrator on one Linux server. It takes a few minutes, and the installer checks your server before it changes anything.

Downloads

You need all three files. The installer needs no internet access once it is on your server.

forge-install-0.1.3.shThe installer, about 38 MB forge-install-0.1.3.sh.sigIts signature fc.pubThe Forge public key, to check the signature

What the server needs

  • Linux on amd64 (x86-64) or arm64, with systemd, and sudo access
  • Docker with Compose v2, or Podman 5 or later with podman compose. On Ubuntu 22.04 use Docker, because its Podman is too old.
  • openssl and curl, which most servers already have
  • At least 2 GB free disk and 1.5 GB free memory for Forge, plus what your model needs
  • A local ext4 or XFS disk for /opt/forge and for the container storage (not NFS)
  • Ports 8080, 8081 and 8084 free, and reachable from your internal network. 9090 and 9091 are used locally only.
  • The clock synced over NTP

Only if you want them (you can also add them later)

  • A model, one of these: Forge runs it with Ollama: an Ollama image in your registry (ollama/ollama:0.40.9) and a folder with the GGUF file and a Modelfile. Forge runs it with vLLM: a vLLM image (vllm/vllm-openai:v0.32.0), a model folder, and an NVIDIA GPU with the NVIDIA container toolkit. You already run it: the address of your Ollama, vLLM or other OpenAI-compatible server, and its API key if it has one.
  • Your private CA file, if your internal APIs or the model use certificates from it
  • Your own certificate and key for the chat API. Without them, Forge creates its own.
  • A Bitwarden or Vaultwarden server, if your APIs keep their secrets there

1Put the files on the server

If the server can reach the internet, download them there:

shell
F=forge-install-0.1.3.sh
U=https://github.com/DevStudiosDigital/forge-releases/releases/download/v0.1.3
curl -fL -O $U/$F -O $U/$F.sig -O $U/fc.pub

If it cannot, download the three files on your computer from the links above, then copy them over, for example:

shell
scp forge-install-0.1.3.sh forge-install-0.1.3.sh.sig fc.pub \
    admin@your-server:

2Check the signature

On the server, in the folder with the three files:

shell
F=forge-install-0.1.3.sh
base64 -d $F.sig > forge-install.sig
openssl dgst -sha256 -verify fc.pub -signature forge-install.sig $F

It must print Verified OK. If it prints anything else, stop and contact us: the file is damaged or is not from Forge.

3Run the installer

shell
sudo sh forge-install-0.1.3.sh

It first checks the server and lists anything missing, with the fix. Then it asks:

  1. The first admin's username and password (at least 14 characters).
  2. Do you have your own certificate? Answer n and Forge creates one. It then shows the names and IPs it found; add any other name or IP your apps use to reach this server, such as a public IP or DNS name.
  3. Optional setup: a model, your private CA, Bitwarden. Press Enter to skip them; you can add each one later.
If you connect a model server you already run, the installer calls it from the server and from inside Forge before saving anything, and tells you what to fix if it cannot reach it. A server on the same machine must listen on 0.0.0.0, not only on 127.0.0.1.

4Open Forge and publish your first tool

At the end the installer prints everything you need:

WhatAddressSign in with
Control Stationhttp://<server>:8084/The admin you just created
Chat API for apps (OpenAI-compatible)https://<server>:8080/v1The API key: sudo cat /opt/forge/stack/secrets/orch-api.key
MCP clientshttp://<server>:8081/mcpThe token: sudo cat /opt/forge/stack/secrets/mcp.token

Open the Control Station, sign in, go to MCP Server → APIs → Import OpenAPI, then test and publish a tool.

With the certificate Forge created, give your apps the file /opt/forge/stack/certs/forge-ca.pem so they trust it.

The Control Station (8084) and MCP Server (8081) use plain HTTP. Reach them only over your internal network or VPN.

If another program on the server already uses the name forge, run sudo /opt/forge/bin/forge instead.

If something goes wrong

Fix what the installer reports and run the same command again. It keeps what it already set up and asks the questions again.

If you need us, send the file this command writes (it contains no keys or passwords):

shell
sudo forge doctor

If the install stopped before Forge was set up, send /var/log/forge-install.log instead.
